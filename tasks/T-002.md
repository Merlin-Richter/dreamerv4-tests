## Objective

A frozen, reusable instrument that measures **how well a world model recalls hidden
state (ball color, ball position) after the revealing frames have left its context
window**, as a function of occlusion length k. Used for: the H2 baseline, and every
later H3 method comparison. Once frozen, any change is a logged decision (§8).

## Why a new dataset (not `occluded.npy`)

The existing generator deliberately keeps occlusion runs short ("comfortably fit inside
the dynamics window") — the *opposite* of H2. The probe needs controlled episodes whose
the **occlusion length** spans **below → above** the inference window N, and exact
ground truth. We drive `OccludedBouncingEnv` directly (it exposes `env.color`,
`env.x/y`, `env.vx/vy`), so GT color+position need no detection on the GT side.

### Notation (read first — avoid the K collision)
- `N`       = sliding **context window** = frames the model can attend to. **N = 8**
              (confirmed Merlin 2026-06-12). Model was trained at 16; running at 8 is
              free (M<N, RoPE-relative, no retrain).
- `n_occ`   = **occlusion length** = number of consecutive curtain-DOWN frames. THE
              swept variable. (Earlier drafts wrote this as "k" — that was a bad
              collision with `K` and is renamed everywhere.)
- `K`       = diffusion/shortcut **sampling steps** per frame (`inference_steps`, =4).
              Unrelated to the above; left at its default.
- `P`       = **visible prefix** = curtain-UP frames before the occlusion, so the ball
              is observed first. P=3 (≥2 needed to observe velocity).

## Probe episode structure (per trial)

```
[ visible prefix: P frames,     curtain UP ]   → ball color+position+velocity observable
[ occlusion:      n_occ frames, curtain DOWN ] → ball keeps bouncing, hidden
[ reveal:         R frames,     curtain UP ]   → MEASURE recall on the first reveal frame
```
- **P = 3** (confirmed). **R = 1.**
- **`n_occ` swept across the window N=8:** `{2, 4, 6, 7, 8, 9, 12, 16, 24}`.
  - `n_occ < ~7`: visible prefix still inside the 8-frame window → model can attend
    back to it → recall via in-context attention (NOT a memory test).
  - `n_occ ≥ ~8`: prefix has scrolled out of the window → recall requires the model to
    have *carried the info forward*. A vanilla sliding-window model can't → recall
    falls off a cliff to chance. The cliff at ~N is the H2 result.
  - (Window note: `generate()` uses `max_ctx = N-1 = 7` past frames when predicting the
    reveal frame, so the prefix is fully gone once `n_occ ≥ 7`.)
- **64 episodes per `n_occ`** (independent seeds → varied colors/positions/velocities),
  averaged. **[CHECK]** count only.

## Rollout protocol

1. Generate the GT episode with the env; record frames, per-frame action stream
   (0=up,1=down), GT (x,y) per frame, GT ball color (`env.color`, dataset-native order
   — NO channel swap, per the probe_env channel-order contract).
2. Encode the **visible prefix** with the frozen tokenizer → context latents
   (1, P, n_lat, dim). **Pure generation** (confirmed Merlin 2026-06-12): the occluded
   frames are generated by the model, not fed from GT-encoded curtain latents.
3. `gen = model.generate(context, n_generate=n_occ+R, K, action_idx)` where `action_idx`
   covers all P+n_occ+R frames (the model is told curtain-down for n_occ then up at
   reveal). The sliding window inside `generate()` drops the prefix once seq exceeds N.
4. Predicted reveal latent = `gen[:, -1]`. Decode the full predicted sequence for the
   pixel-space readout / visualization.

## Metrics

**Primary — latent-token MSE (decoder-free, detection-free).**
`MSE( predicted_reveal_latent , GT_reveal_latent )` where `GT_reveal_latent =
encode(full GT clip)[reveal_index]` (encode the whole true clip so the causal-temporal
tokenizer gives the same target the dynamics model is trained against — **not** a
single-frame encode). Report vs `n_occ`.

**Interpretable decomposition (pixel-space, the validation + Figure-1 view).**
Decode the predicted reveal frame, then:
- **Position recall:** detect the ball (bright blob on dark bg → threshold in HSV
  value / connected components) → centroid → error vs GT (x,y) in pixels.
- **Color recall:** mean RGB inside the detected blob vs GT `env.color` (ΔRGB, and
  hue error). Detection-free cross-check: also read predicted color at the GT centroid.
- **Ball-lost rate:** fraction of trials with no detectable blob — its own failure mode
  (the measurement-validity issue Merlin flagged: if there's no ball, color is N/A, not
  fudged).

**Metric-validation step (D-011 tripwire):** does latent-MSE-vs-`n_occ` track the
color/position errors? If yes → latent-MSE is the H2 headline. If they diverge →
escalate before pre-registering; the divergence is itself a finding.

## Controls (calibration references; measured, not the H2 test itself)

- **Chance floor:** prediction with no usable context (random latent / curtain-only
  context) — where recall bottoms out.
- **Ceiling:** reveal frame with `n_occ=0` (fully visible context) — best achievable.
- **No-occlusion drift control:** roll out the same number of steps with curtain UP
  throughout; differences out ordinary autoregressive drift so recall-loss is
  attributable to occlusion, not generic rollout degradation.

## Deliverables / structure

- `src/probe/probe_env.py` — controlled probe-episode generator (driving the env).
- `src/probe/revisit_probe.py` — rollout + metrics + controls; emits `results.json`
  (per-`n_occ` arrays) + a side-by-side sheet (GT top row / prediction bottom row,
  columns = time, reveal column marked).
- `src/probe/README.md` — frozen-version note + exact command to reproduce.
- Deterministic (fixed seeds). Runs locally on the 4070.

## Acceptance criteria (machine-checkable)

1. `python -m src.probe.revisit_probe --dry-run` produces schema-valid `results.json`
   with keys: `occ_grid`, `latent_mse_by_occ`, `pos_err_px_by_occ`, `color_dRGB_by_occ`,
   `ball_lost_rate_by_occ`, plus `controls.{chance,ceiling,drift}`.
2. Ceiling (`n_occ=0`) latent-MSE ≈ the model's known good gen quality; chance floor
   clearly worse — i.e. the instrument separates the trivial cases (sanity gate).
3. Ball detector validated on **GT** revealed frames: centroid error < 1.5 px and
   color ΔRGB < 10 on ≥99% of GT frames (else the detector, not the model, is the
   problem — instrument rejected).
4. Latent-MSE-vs-`n_occ` and pos/color-vs-`n_occ` both produced for the existing
   `my_dynamics.pt` baseline; correlation reported (the validation step).
5. Side-by-side sheet renders for a sample of `n_occ` values.

## Freeze procedure

On acceptance: commit, tag the commit SHA in `src/probe/README.md` and the
EXPERIMENTS.md entry, and treat the suite as frozen. The H2 baseline run (separate EXP)
then uses it unchanged. Any later edit → logged decision (§8).
