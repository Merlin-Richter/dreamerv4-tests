# T-001 — Context-noise rollout diagnostic (EXP-008 harness)

Spawned by: D-010 (sharpens D-009 candidate (a)). Local only (RTX 4070). No cluster.

## Objective

Build a **headless** diagnostic script that tests the hypothesis that the
EXP-007 dynamics rollout failure is caused by the rollout context-noising in
`DynamicsModel._denoise_next`: `config.context_noise` (tau_ctx) is the *signal
level*, so the default 0.1 means the context frames are 90% noise (see D-010).
The script sweeps tau_ctx on the **existing** checkpoint (no training) and saves
visual + quantitative comparisons. You build and smoke-test it; the orchestrator
runs the full sweep.

## Background pointers (read these, do not paste them around)

- `src/D_dynamics_model/dynamics_model.py` — `DynamicsModel`. Key methods:
  `generate(context, n_generate, K, action_idx)`, `_denoise_next(...)` (reads
  `self.config.context_noise` at call time — mutating `model.config.context_noise`
  between rollouts is sufficient to sweep, no signature change needed), and `loss`
  (shows the tau=signal convention: `z_tilde=(1-tau)*z0+tau*z1`).
- `src/D_dynamics_model/train_dynamics_model.py` — reuse the **loading and decode
  path** from `run_test_checkpoint` (lines ~138-235): `load_tokenizer`,
  `encode_frames`, `_config_from_checkpoint`, building `DynamicsModel` from the
  checkpoint config, action-stream handling for `n_actions>0`, and the
  `latents = encode(...) → context = latents[:, :n_ctx] → gen = model.generate(...)
  → recon = tokenizer.decoder(torch.cat([context, gen]))` flow. That function uses
  `cv2.imshow` (needs a display) — your script must instead **save PNGs to disk**,
  no GUI.
- Tokenizer (frozen, EXP-007's): **`trained_autoencoder.pt` at repo ROOT** — NOT
  the train-script default `src/C_multi_image_auto_encoder/autoencoder_bouncing.pt`.
  Pass it explicitly.
- Dynamics checkpoint: **`my_dynamics.pt` at repo ROOT** (EXP-007, action-conditioned
  n_actions=2, config in `experiments/EXP-007/NOTES.md`).
- Data: `occluded.npy` (N,T,H,W,3 uint8, memmap with `mmap_mode="r"`) +
  `occluded_actions.npy` (N,T) at repo root. Action-conditioned model → the
  per-frame action stream IS required for a correct rollout (curtain state).

## What to build

`experiments/EXP-008/diagnose_context_noise.py`, headless, deterministic
(seed everything; fixed episode selection so reruns are comparable). It must:

1. Load frozen tokenizer (`trained_autoencoder.pt`) + dynamics (`my_dynamics.pt`)
   on cuda; eval mode; no grad.
2. Select a fixed set of episodes (default 6; CLI `--n-episodes`, `--seed`). For
   each, take a clip of length `cfg.max_temporal_length` (16), use `--context-frames`
   (default 4) ground-truth context, generate the rest, with the aligned action
   stream.
3. Sweep `tau_ctx ∈ {0.1, 0.5, 0.9, 0.99}` (CLI `--tau-ctx-list`, comma-sep) by
   setting `model.config.context_noise` before each `generate`. Keep K at the
   checkpoint default (4); also accept `--inference-steps`.
4. For each (episode, tau_ctx): decode the full sequence and save a PNG named
   `ep{E}_tau{TAU}.png` laid out as **GT frames on the top row, decoded rollout on
   the bottom row, time advancing left→right**, with the context/generation
   boundary marked (a vertical line at column `n_ctx`, as in `run_test_checkpoint`).
   Put all PNGs in `experiments/EXP-008/images/`.
5. Also save one **per-tau contact sheet** stacking the episodes vertically so the
   effect of tau_ctx is visible at a glance (optional but preferred).
6. Write `experiments/EXP-008/results.json`: for each tau_ctx, the mean (over
   episodes) per-generated-frame pixel-MSE between decoded rollout and GT frame
   (i.e. only the generated frames, not the copied context), plus the overall mean.
   Schema:
   ```json
   {"checkpoint": "...", "tokenizer": "...", "n_episodes": 6,
    "context_frames": 4, "K": 4, "seed": 0,
    "by_tau": {"0.1": {"gen_mse_per_frame": [...], "gen_mse_mean": 0.0}, ...}}
   ```
7. Print a one-line summary per tau_ctx (tau → gen_mse_mean) at the end.

Keep it dependency-light: torch, numpy, and `cv2` or `imageio`/`PIL` for PNG write
(no matplotlib needed; if you use it, fine). Reuse the `sys.path` insert trick from
`train_dynamics_model.py` so `dynamics_model` and `video_auto_encoder` import.

## Constraints

- Headless: must run with no display (`cv2.imwrite`/`PIL.save`, never `imshow`).
- Do NOT modify `dynamics_model.py` or `train_dynamics_model.py` (this is a
  read-only diagnostic of the existing model). If you find you *must* change a
  source file to make the rollout work, STOP and report it — that's a finding.
- Deterministic given `--seed`.
- No W&B, no cluster.

## Acceptance criteria (must all pass; orchestrator will re-run these)

1. `python experiments/EXP-008/diagnose_context_noise.py --n-episodes 2` runs to
   completion headless on the 4070 in well under 5 min, exit code 0.
2. It writes `experiments/EXP-008/results.json` matching the schema above, with a
   numeric `gen_mse_mean` for every tau_ctx in the sweep.
3. It writes one `images/ep{E}_tau{TAU}.png` per (episode, tau_ctx), each a
   2-row (GT / rollout) strip with the context boundary marked.
4. Re-running with the same seed produces identical `results.json` numbers.
