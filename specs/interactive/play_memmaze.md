# play_memmaze.py — playable Memory Maze rendered by the dynamics model.

The neural twin of `external/memory-maze/gui/run_gui.py` (the real playable Memory Maze): the same
pygame window, keymap and pacing — but every frame after the context is generated by the trained
dynamics model's carrying rollout in the frozen tokenizer's latent space (local GPU), instead of
MuJoCo. You play *inside the world model*: walk the maze from memory and eyeball whether the model
keeps the maze consistent when you look away and back.

## Interface
- CLI: `--checkpoint <dynamics.pt> --tokenizer <frozen.pt>` required; `--frames` (default
  `data/memmaze9x9_val12.npy`, held-out episodes) with the `<stem>_actions.npy` sidecar
  auto-detected (`--actions` overrides; `<stem>_ids.npy` used for display when present);
  `--n-ctx` (default = the model's `max_temporal_length`; must be ≤ the tokenizer window —
  one-shot encode); `--decode-ctx` (default 16) trailing latents given to the temporal decoder;
  `--K` (default 4) shortcut steps; `--window` forces a shorter sliding window (total frames, like
  the recall eval); `--episode` fixes the episode index; `--seed` seeds episode/offset sampling;
  `--size`/`--fps`/`--fullscreen`/`--nonoop` as in `run_gui.py`; `--selftest N` (headless smoke
  mode, below).
- Keymap (identical to `run_gui.py`): no key = 0 (noop), ↑ = 1 (forward), ← = 2 (turn left),
  → = 3 (turn right), ↑← = 4, ↑→ = 5 — the dataset's 6 discrete actions. Specials: space = pause,
  backspace = reset (new episode), tab = speed up (held), esc/close = quit.

## Behavior
- Load the dynamics checkpoint + frozen tokenizer (inference-only, no grad). An action-conditioned
  model (`n_actions>0`) without an actions sidecar is an error (an unconditioned memmaze rollout is
  meaningless); an unconditioned model plays with keys ignored (warned).
- **Reset**: sample (episode, start) — uniform offset such that `n_ctx` real frames fit — encode
  the `n_ctx` context frames one-shot, and commit them with their TRUE recorded actions via
  `rollout_init` (written-memory relay seed for memory models). The context is then REPLAYED on
  screen frame-by-frame at the display fps (phase label `CTX REPLAY (real)`) so the player sees
  exactly the walk the model saw — the memorization phase of the memory test. Action keys are
  inert during replay; pause/speedup/reset/quit still work.
- **Play**: after the replay, each display tick resolves the held-key combo to an action id
  (last all-pressed keymap entry wins, as in `run_gui.py`) and takes ONE committed
  `rollout_step(state, action, commit=True)` — the persistent-state form of the exact loop
  `model.generate` runs internally (carrying KV cache, memory relay when `n_memory>0`). The new
  latent is appended to a trailing `decode-ctx` latent buffer and the frame displayed is the LAST
  frame of the temporal decoder applied to that buffer (safe by the window-invariance probe:
  window-delta recon error ≪ recon error). Phase label `ROLLOUT (model)`. With `--nonoop`, no keys
  = no step (pause-like) instead of stepping a noop. The rollout has no terminal state — it runs
  (sliding/evicting past the window) until reset or quit.
- Side panels mirror `run_gui.py`: left = stats (episode id — the original dataset id when the
  `_ids` sidecar exists — start offset, phase, step, action name, per-step model ms + achieved
  fps, window, `n_memory`, device); right = keymap help.
- `--selftest N` runs the SAME loop headless (SDL dummy video driver, speedup forced, scripted
  action cycle after the replay), auto-quits after `N` generated frames and prints per-step
  latency stats — the smoke gate that reset + rollout + render run clean without a human.

## Invariants
- Rollout state is initialized ONCE per reset by `rollout_init` and advanced only by
  `rollout_step(commit=True)` — no re-`generate` from the latent history per tick, no snapshot /
  FF7 special branches.
- Frames are treated in the STORED channel order end-to-end (memmaze `.npy` keeps the env's RGB
  as-is; pygame consumes RGB, so display is pass-through — no swap anywhere).
- Context actions are the episode's TRUE recorded actions; play actions come only from the
  keyboard. The context replay shows the raw dataset frames, not reconstructions.
- pygame is a viewer-only dependency (repo venv); the model path (reset/step) must not import it.
